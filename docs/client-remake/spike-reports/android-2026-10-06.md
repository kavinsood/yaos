## Consequences
- **OR-1 (Android):** the Blob-URL worker plus IndexedDB in the worker is viable, so the engine runs in the worker.
- **OR-2 A/B/R:** the per-instance `setViewData` wrapper sees every external reload: `vault.modify`, raw `adapter.write`, and reading mode. External writes do not bypass it.
- **OR-2 C:** "handled" without applying the incoming text is data loss. The editor keeps the old text and the next save overwrites the disk. The wrapper must always merge into the editor (the C2 pattern) or restore `view.data`.
- **OR-2 A detail:** Obsidian's `setData` assigns `view.data = incoming` *before* calling `setViewData`. Code that reads `view.data` inside the wrapper as the "last saved base" gets the incoming text instead.
